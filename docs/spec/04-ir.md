# 04 Semantic IR

- **Version:** v0 (draft), 2026-09-30
- **Part:** the serializable form of the core semantics (R-47, D-019, D-036, D-037). It carries what `01` to `03` assign to each construct; it adds no meaning.
- **Scope:** the model, presentation and run IR for the first slice. The reference implementation is the `prismal-ir` crate (`crates/prismal-ir`), whose types are normative for field names in v0.

---

## 1. Principles

- **Restates:** R-45, R-47, R-66.
- **Decisions:** D-019, D-028, D-036, D-037, D-039, D-048, D-049, D-050, D-051.
- **Prior art:** follows compiler intermediate representations that are separate from syntax trees (Rust's HIR and MIR, the Modelica flat model); follows FMI's `modelDescription.xml` in describing a model's variables, causality and variability in a tool-neutral file; follows JSON Schema practice for versioned documents.

- **IR-1.1** The IR records what the author **meant** (R-47): resolved identities, roles, types, flow kinds, trigger directions. It does not record layout, keyword spelling or the choice between equivalent surface forms. A syntax tree is a separate, tool-internal structure.
- **IR-1.2** The IR is **complete**: every construct of `01` to `03` has a form here, and a model can be built, checked, run and printed from the IR alone, without source text (D-019).
- **IR-1.3** The serialization is **JSON** (D-037), UTF-8, with a format tag and version. Numbers are binary64; a writer MUST print them so that reading gives back the same binary64 value (shortest round-trip form).
- **IR-1.4** Every declared element has an **identity** (`id`): an opaque string, unique within the document, stable across edits that do not remove the element (MK-7.6, D-036). References between elements use identities, never names.
- **IR-1.5** Every declared element MAY carry **notes**: the author's documentation comments (D-036). Notes have no meaning; tools preserve them.
- **IR-1.6** Elements MAY carry a **source span** (file, line, column) for diagnostics. Spans have no meaning and are dropped when the IR is edited visually.
- **IR-1.7** Order: the order of elements in a list is their **identity order** where the kernel needs one (MK-13.6, MK-14.10). Tools MUST preserve it; a new element is appended.

## 2. Document

```json
{
  "format": "prismal-ir",
  "version": "0.1",
  "spaces": [ ... ],
  "models": [ ... ],
  "presentations": [ ... ],
  "runs": [ ... ],
  "uses": [ {"module": "mechanics", "names": ["Body"] | absent}, ... ],
  "libraries": [ {"name", "enums", "functions", "objects"}, ... ]
}
```

- `uses` and `libraries` (D-099, MK-7.1a): the modules the document imports, and the shared definitions of the document itself (the library named `shared`) and of every module it uses, directly or through another module. A document is complete without its modules' files. Identities in a library are those of a model named after it: `shared.Body`, `mechanics.fn.kinetic_energy`, `shared.enum.Heading`. Points and vectors in a library are of the space `@space`. Linking (`prismal_ir::link`) copies into each model the library definitions it reads, directly or through each other, with `@space` replaced by the model's space and identities kept, before elaboration and checking; it is not part of the authored IR.

## 3. Dimensions, units and types

- **Dimension:** an object of rational exponents over the seven SI base dimensions, omitting zeros: `{"L": 1, "T": -2}`; a rational exponent is written `[1, 2]`. The empty object is dimensionless (MK-3.1).
- **Unit** (in literals and display metadata): `{"text": "m/s^2", "scale": 1.0, "offset": 0.0, "dim": {"L": 1, "T": -2}}`. `text` is what the author wrote and is used only for display (MK-3.7).
- **Type:**

| Kind | JSON |
|---|---|
| Boolean, Integer | `{"kind": "boolean"}`, `{"kind": "integer"}` |
| Quantity (Real is dimensionless) | `{"kind": "quantity", "dim": {...}}` |
| Instant | `{"kind": "instant", "dim": {...}}` |
| Point, Vector | `{"kind": "point", "space": id}`, `{"kind": "vector", "space": id, "dim": {...}}` |
| Tuple | `{"kind": "tuple", "items": [type, ...]}` |
| Enumeration | `{"kind": "enum", "enum": id, "cases": ["flying", "grounded"]}`: the identity of its declaration (5.5), which makes it nominal (MK-2.2), and its cases in declaration order |
| Function | `{"kind": "function", "params": [type, ...], "result": type}` |

## 5. Models

```json
{
  "id": "m1", "name": "Projectile", "default_space": "s1", "notes": [],
  "enums": [ ... ], "bindings": [ ... ], "functions": [ ... ], "processes": [ ... ],
  "flows": [ ... ], "events": [ ... ], "equations": [ ... ], "constraints": [ ... ]
}
```

### 5.1 Bindings

`{"id", "name", "role", "type", "init", "def", "intervenable", "private", "display": {"symbol", "unit"}, "notes", "combine"?}` (`combine`: the combination of contributions to discrete state, D-073)

- `role`: `constant`, `parameter`, `input`, `discrete`, `continuous`, `derived`, `unknown` (MK-6.2, D-092).
- `init`: the initial definition (stored roles except `input`); for an `unknown`, its guess (MK-11.6), or null for 0. `def`: the defining expression (`derived`); for a derived function value (MK-10.7) it is a `lambda`.
- `intervenable`: explicit for state; parameters are intervenable unless it is `false` (MK-6.10).

### 5.2 Processes and flows

- Process: `{"id", "name", "kind": "continuous", "notes"}` (MK-14.1).
- Flow: `{"id", "target": binding-id, "kind": "define" | "contribute", "expr", "process": id | null}` (MK-14.7).

### 5.3 Events

`{"id", "name", "trigger", "enable", "handler": [op, ...], "zeno", "payload": {"name", "type"} | null, "algorithm": [stmt, ...]?, "notes"}`; an algorithm (MK-14.17, D-101) has statements and an empty handler: `{"stmt": "do", "ops": [op, ...]}` (operations performed together; one written operation may become several in elaboration), `{"stmt": "if", "if": expr, "then": [stmt, ...], "else": [stmt, ...]?}`, `{"stmt": "while", "while": expr, "body": [...]}`, `{"stmt": "for", "var": binding-id, "from": expr, "to": expr, "body": [...]}`, `{"stmt": "step"}`; the checker adds the hidden discrete binding `event-id@resume` when the model has none; the payload's name is for display and printing (MK-15.1a, D-050). A member payload has `"of": part-id` and type `Real`, the member's number; elaboration adds `"members"`, the collection's path in the flat model (`"balls"`), by which hosts name members. Several payloads are `{"name": "b, j", "type": {"kind": "tuple", ...}, "items": [payload, ...]}`, each item read as `{"comp": {"payload": event-id}, "axis": k}` and supplied as a tuple (MK-15.1c, D-059)

- Trigger: `{"kind": "falling" | "rising" | "crossing", "guard": expr}`, `{"kind": "at", "time": expr}`, `{"kind": "every", "period": expr, "from": expr}`, `{"kind": "on", "event": id}`, `{"kind": "start"}`, `{"kind": "input", "binding": id}`, `{"kind": "request"}`, `{"kind": "random", "rate": expr}` (D-083). The form `{"kind": "level", "cond": expr}` exists only so that invalid IR (RP-01.D1) can be represented and rejected (MK-E13).
- Zeno: `null`, `{"policy": "stop"}` or `{"policy": "settle", "ops": [...]}`, with optional `eps`, `n`, `window` (MK-15.13).
- Operation: `{"op": "set", "target": {"binding": id, "component": null | index}, "value": expr}`, `{"op": "contribute", ...}`, `{"op": "emit", "event": id, "payload": expr | null}`. A target may carry `"member": e`, the member whose binding it is, when a container's handler writes it (D-057). On collections whose membership changes (D-057): `{"op": "create", "part": part-id, "overrides": [{"binding", "value"}, ...]}` and `{"op": "destroy", "member": e}`; elaboration turns them into sets of liveness bindings, `{"op": "destroy", "member": {"ref": liveness-binding-id}}`, and conditional operations `{"op": "if", "if": e, "then": [op, ...]}`, performed when `if` holds on the state before the transition. A member is made by `{"op": "make", "alive": liveness-binding-id, "values": [{"binding", "value"}, ...]}`, whose values may set parameters (MK-16.1a). Relations (D-058): `{"op": "connect", "part": part-id, "ends": [member, ...], "overrides": [...]}` and `{"op": "disconnect", "relation": member}`.

### 5.4 Equations and constraints

- Equation: `{"id", "name", "lhs", "rhs", "role": "display" | "check", "tol": expr | null}` (MK-11). A `display` equation that reads an unknown is a solved equation (MK-11.7); it has no role of its own. The authored IR keeps `der(x)` in equations as written; the hidden unknowns and flows of MK-11.9 are added by elaboration, with identities `x@rate` and `x@rate.flow`, and do not appear in the authored IR.
- Constraint: `{"id", "name", "cond", "tol": expr | null, "policy": "reject" | "report" | "stop" | "enforce", "attached_to": binding-id | null, "force": binding-id | null, "bound": expr?, "restitution": expr?}` (`bound`, `restitution`: MK-12.12, MK-12.13, D-102; the checker adds the hidden bindings `id@hold` and `id@side` and their events, and an inequality with restitution gets the operation `{"op": "rebound", "constraint": id}` on its touch event) (MK-12). `force` is the unknown that holds an enforced inequality, `with N` (MK-12.11, D-098); for each such constraint the checker adds a private discrete `Boolean` binding `c@contact` and the events `c@touch`, `c@release`, `c@settle` and `c@start` (RC-5.11), never in the authored IR. For an enforced constraint (MK-12.6, D-093) the checker adds, to the model it checks and never to the authored IR, the solved rate as an equation with the identity `c@solved` (`c` the constraint's identity), and for each continuous state with a flow a private derived binding `x@flow` holding its rate, so a flow read inside a rate keeps the type its tuples take from the state.

### 5.5 Enumerations and functions

- Enumeration: `{"id", "name", "cases": [text, ...], "notes"}` (MK-2.2a, D-049). Identity `Model.enum.Name`.
- Function: `{"id", "name", "params": [{"name", "type"}, ...], "result": type, "body": expr, "notes"}` (MK-10.3a, D-048). Identity `Model.fn.name`. The body reads parameter `i` as `{"param": i}`; parameter names are for display and printing. `attached_to` records that the author wrote the constraint on a parameter (`where`, `in`), so it prints back there (D-028); it has no meaning.

### 5.6 Objects and parts

- A model's `objects` are its object types (MK-7.13, D-055), each with the fields of a model; identity `Model.Name`, so its bindings are `Model.Name.x`.
- A model's (or object type's) `parts`: `{"id", "name", "object": object-type-id, "count": n | absent, "overrides": [{"binding": id, "value": e}, ...], "notes"}`. Identity `Model.part.name`. Without `count` the part is one object. Override values are read in the container's scope, where `{"builtin": "index"}` is the member's number.
- A flow may carry `"member": e` (the member whose binding `target` is: a part, an item or a loop variable) and `"each": {"var": text, "over": part-id}` (the flow is repeated for each member).
- A representation may carry `"each": {"var", "over"}` (one representation per member, `name[k]`).
- An object type with `"ends": [{"id", "name", "over": part-id}, ...]` is a relation type (D-058); endpoint identities are `Model.Rel.a`, and a part of that type is a relation set, whose starting relations give their endpoints as overrides with a member as the value. Elaboration adds, for each relation `rs[k]`, a private discrete `Real` binding per endpoint, `Model.Rel.a@rs[k]`, holding the member's number in its collection. A derived binding may carry `"when": e` (made by elaboration): it is evaluated only while `e` holds and otherwise has no value. A relation type with `"undirected": true` has two endpoints over one part (D-064). A part reference (an endpoint's `over`, an item, an aggregate, a loop) may be a **part path**: the identities of contained objects and then of a part inside the last of them, joined by `/` (`Cells.part.left/Cells.Cell.part.atoms`, D-065).
- A part may carry `"capacity": n` (D-057): its membership changes, it starts with `count` members (none when absent) and makes at most `n` in a run. An event may carry `"each": {"var", "over"}` (the event is repeated for each member, named `name[k]`).
- Elaboration of a collection with a capacity adds, for the part `P` in the container at `path`: a private discrete `Real` binding `P.created` (identity `part-id.created`, with `@path` inside a member), counting the members made; for each member at `c[k]`, a private discrete `Boolean` binding `part-id.alive@c[k]`; and a `stop` constraint `P.capacity`. A member's flows, events, equations and constraints are guarded by its liveness, its representations carry `"when"`.
- Elaboration (`prismal_ir::elaborate`) turns a document with parts into one without, before checking (MK-8.3b): identities `declaration@path`, names `path.name`.

## 6. Expressions

Every expression is an object with one tag field. Expressions keep their symbolic structure (MK-10.6).

| Form | JSON |
|---|---|
| number literal | `{"num": 9.81, "unit": unit | null}` |
| Boolean literal | `{"bool": true}` |
| enumeration case | `{"case": "flying"}` |
| binding read | `{"ref": id}` |
| lambda parameter | `{"param": index}` |
| built-in | `{"builtin": "t" | "t0" | "elapsed" | "index"}`; `index` only in the overrides of a collection (D-055) |
| named constant | `{"const": "pi"}` (D-039) |
| origin | `{"origin": space-id}` |
| derivative | `{"der": binding-id}` (MK-11.5) |
| unary | `{"neg": e}`, `{"not": e}`, `{"norm": e}` |
| binary | `{"bin": "add" | "sub" | "mul" | "div" | "pow" | "and" | "or" | "eq" | "ne" | "lt" | "le" | "gt" | "ge", "l": e, "r": e}` |
| function call | `{"call": "sin" | "cos" | "tan" | "sqrt" | "exp" | "log" | "abs" | "min" | "max" | "atan2" | "dot" | "cross" | "floor" | "ceil" | "round" | "mod", "args": [e, ...]}` |
| draw (D-083) | `{"draw": "uniform" | "normal" | "exponential" | "bernoulli" | "integer" | "poisson" | "binomial" | "choice", "args": [e, ...]}`; only in an event's enabling condition and operations (MK-10.4) |
| application | `{"apply": e, "args": [e, ...]}` |
| conditional | `{"if": e, "then": e, "else": e}` |
| tuple | `{"tuple": [e, ...]}` |
| component | `{"comp": e, "axis": index}` |
| lambda | `{"lambda": {"params": [type, ...], "body": e, "names": [text, ...]}}`; `names` are the parameter names as written, for display only (`f(x) = a x^2`, D-034) |
| status handling | `{"otherwise": e, "default": e}` |
| declared function | `{"fn": id}`, a function value; `{"apply": {"fn": id}, "args": [...]}` calls it (D-048) |
| match | `{"match": e, "arms": [{"case": text, "value": e}, ...]}`, one arm per case (MK-10.2, D-049) |
| payload | `{"payload": event-id}`: the payload of the occurrence being handled, in that event's condition and handler (D-050) |
| member's binding | `{"field": binding-id, "of": member}`; the binding is declared in the member's object type (D-055) |
| member | `{"part": part-id}` (one object), `{"item": part-id, "index": e}` (a member by a constant number), `{"var": text}` (a loop variable); members are compared with `eq` and `ne` |
| aggregate | `{"aggregate": "sum" | "min" | "max" | "any" | "all" | "count", "var": text, "over": part-id, "body": e, "filter": e}`; `count` has no body (MK-8.3a) |
| endpoint | `{"end": end-id, "of": member}`: the member at an endpoint of the relation `of`, or of the relation whose type is being read when `of` is absent (D-058) |
| pick | `{"pick": e, "from": [e, ...]}`: the item numbered `e` from 1, only it evaluated; made by elaboration for a binding of the member at an endpoint (D-058) or chosen by a computed number (D-101), and written `(a, b, c)[k]` for a list of values (D-101) |
| other | `{"other": member, "rel": relation}`: the endpoint of a relation that is not the member (D-064); a member, not a value |
| has | `{"has": member, "rel": relation}`: whether the member is an endpoint of the relation (D-064) |
| extreme | `{"extreme": "min" | "max", "terms": [{"when": e, "value": e}, ...]}`: the least or greatest value whose `when` holds, no value when none does; made by elaboration for `min` and `max` over a collection whose membership changes (D-057) |

- Chained comparisons lower to `and` of pairwise comparisons.
- A tuple's vector type (D-032) is decided by the checker and is not stored; the IR stays what the author wrote.
- Literal magnitudes are stored as written, with their unit; the checker converts to coherent SI (MK-3.7). A minus sign written directly on a number literal belongs to the literal: `-5` is `{"num": -5}`.
- The IR holds no infinities (JSON cannot represent them): an unbounded interval end lowers to a one-sided comparison.

## 7. Presentations and runs

The reference implementation is `crates/prismal-ir/src/present.rs`. Expressions are model expressions (section 6) read in the scope of the presentation's model; inside an inverse, `{"param": 0}` is the gesture's value. Identities follow declaration paths (D-036): `Pres.observe.name`, `Pres.view.name`, `Pres.scene.name`, `Pres.beat.name`; a representation is `container.name` when named, otherwise `container.kind.n`, the n-th of its kind in its view or beat; a run is its name, and its expectations `Run.expect.n`.

### 7.1 Presentation

`{"id", "name", "model": id, "observations": [...], "instruments": [...]?, "views": [...], "permissions": [...], "timeline": timeline | null, "layout": layout?, "notes", "title": text?, "until": expr?}` (PK-2.1; `title`, D-076; `until`, PK-10.1a, D-091).

- Instrument: `{"id", "name", "resolution": expr?, "range": [expr, expr]?, "noise": expr?}` (PK-3.7, D-087), identified `P.instrument.name`.

- Text: a representation of kind `text` has as sources a text template, with `{}` where each value goes and literal braces doubled, then one expression per `{}`; kind `title` has one text source. A representation's `when`, written by the author as `when: c` or made by elaboration for members, shows it only while it holds (D-057, D-076).

- Layout: `{"view": id}`, `{"row": [layout, ...]}` or `{"column": [layout, ...]}`, the page layout of views (PK-7.4a, D-063).

- Observation: `{"id", "name", "source", "schedule", "instrument": id?}` (PK-3.1; `instrument`, PK-3.7, D-087).
  - Source: `{"kind": "expr", "expr"}`, `{"kind": "event_log", "event": id | null, "zeno_only": bool}`, `{"kind": "diagnostics", "element": id | null}`, `{"kind": "intervention_log"}`.
  - Schedule: `{"kind": "live"}`, `{"kind": "every", "period"}`, `{"kind": "at", "time", "runs"?}` (`runs`: over that many runs, PK-3.8, D-084), `{"kind": "on", "event": id, "microstep": n | null}`, `{"kind": "over", "from", "to": expr | null, "lo_closed", "hi_closed"}` (a null `to` is the end of the run), `{"kind": "run"}` (no schedule written: the whole run).
- View: `{"id", "name", "kind", "representations": [...], "click": click?}` with kind `{"kind": "spatial", "space": id, "scale": scale, "y_up": bool, "look": [expr, expr]?}` (look: the azimuth and elevation of a view of a space of three dimensions, PK-7.2a, D-100), `{"kind": "plot", "x": [lo, hi], "y": [lo, hi], "follow": [bool, bool]?, "units": [unit?, unit?]?, "window": expr?}` (follow, units and window: D-070) or `{"kind": "panel"}` (PK-7.2, PK-7.3).
- Scale: `{"quantity": expr, "px": n}`: the quantity maps to `n` view pixels (PK-5.5).
- Representation: `{"id", "name": text | null, "kind", "sources": [arg, ...], "props": [{"name", "value": arg}, ...], "inverse": inverse | null, "members": [representation, ...], "when": expr | null}` (PK-6.1); `when`, made by elaboration, draws the representation only while it holds (a member alive, D-057); `members` is present only for a `group` (PK-6.3b, D-043), whose members are identified within it (`P.view.scene.body.marker.1`). An argument is `{"kind": "expr", "expr"}`, `{"kind": "text", "text"}`, `{"kind": "range", "lo", "hi"}`, `{"kind": "scale", "scale"}`, `{"kind": "word", "word"}` (a view's orientation; the style properties `color` and `line`, PK-6.6a, D-061; the runtime control of a `button`, `reset`, `undo` or `redo`, D-069, or `reseed`, D-084), for a sampled source (PK-6.3a) `{"kind": "sampled", "expr", "every", "instrument": id?}`, for an ensemble source (PK-3.8, D-084) `{"kind": "ensemble", "expr", "at", "runs", "instrument": id?}` (`instrument`: read through it, PK-3.7, D-087), for the values at each occurrence of an event (PK-6.3e, D-089) `{"kind": "on", "expr", "event": id, "instrument": id?}`, or, for a model element that is not a value (an event for `button`, an equation for `equation`), `{"kind": "element", "element"}`. Several texts, a slider's `ends`, are `{"kind": "texts", "texts": [text, ...]}` (D-077). The timeline action `hide` is `{"action": "hide", "target", "duration"?}`; `reveal` is `{"action": "reveal", "view"?, "style": "fade" | "draw", "duration"?, "reps"}` and `camera` is `{"action": "camera", "view", "center"?, "zoom"?, "duration"?}` (D-042).
- Inverse: `{"gesture": "drag", "part": text | null, "proposals": [{"target": binding-id, "value": expr, "member": expr?}, ...]}` (PK-5.6); `member`, in a representation repeated per member, names the member whose binding `target` is (`{"var": "b"}`), and elaboration replaces it by that member's binding (PK-10.5a, D-059).
- Inverse: `{"gesture": "drag", "part"?, "proposals": [{"target", "value", "member"?}, ...], "live"?: true}`; `live` is drag mode `live` (PK-10.9a, D-071).
- Click: a representation's `"click": {"event": event-id, "payload": expr?}` requests that event when the representation is clicked or activated; a member payload is elaborated to the member's number (PK-10.5b, D-059). A view's `click` requests its event when an empty point of the view is clicked; its payload reads the point as `{"param": 0}`, as an inverse's proposals read the gesture value (PK-10.5c, D-060).
- Permission: `{"role": "learner", "allows": ["timeline_controls", "zoom", "pan"]}` (PK-10.4).

### 7.2 Timeline

`{"scenes": [{"id", "name", "beats": [{"id", "name", "actions": [...]}]}]}` (PK-9.1). Each action is an object tagged by `action`:

| Action | JSON |
|---|---|
| show | `{"action": "show", "view": id | null, "reps": [...]}` (`in V { reps }`, or `show rep` over the presentation) |
| highlight | `{"action": "highlight", "target": representation-id}` |
| narrate | `{"action": "narrate", "text", "duration": expr | null}` |
| run, hold | `{"action": "run", "rate": expr}`, `{"action": "hold"}` |
| seek, reset, branch | `{"action": "seek", "time": expr}`, `{"action": "reset"}`, `{"action": "branch"}` |
| intervene, request | `{"action": "intervene", "ops": [op, ...]}`, `{"action": "request", "event": id}` |
| wait, wait_until | `{"action": "wait", "duration": expr}`, `{"action": "wait_until", "event": id}` |
| explore | `{"action": "explore", "limit": expr | null, "keep": [binding-id, ...], "controls": [rep, ...], "fallback": [action, ...]}` |
| sequence | `{"action": "sequence", "actions": [...]}` |
| wait_learner | `{"action": "wait_learner", "limit"?: expr, "fallback"?: [action, ...]}` (a continue point, D-067) |
| animate | `{"action": "animate", "target": representation-id, "property": "opacity" \| "offset" \| "color" \| "line" \| "scale" \| "morph", "to"?: expr, "word"?: text, "duration"?: expr, "ease"?: "linear" \| "smooth" \| "in" \| "out"}`; `to` for opacity, offset and scale, `word` for a color, a line style or the representation a morph takes the shape of (D-068, D-075) |
| release, bind | `{"action": "release", "target"}`, `{"action": "bind", "target", "duration"?: expr}` (D-068) |

The shorthand `run rate r until E` is stored as the two actions `run` and `wait_until` (D-028); the formatter prints them back as the shorthand when a beat holds exactly those two.

### 7.3 Runs

A run case (RC section 3, PK section 4): `{"id", "name", "model": id, "presentation": id | null, "params": [{"binding", "value"}, ...], "config": {"solver", "h", "rtol", "atol"}, "end": expr | null, "learner": [step, ...], "expectations": [...]}`.

- Learner step: `{"at": expr, "input": {"kind": "continue"} | {"kind": "set_control", "control": "slider", "binding": id, "value": expr} | {"kind": "press", "event": id}}` (`press`, D-069). A learner script is test-harness input fed through the interaction path (reference programs README).
- Expectation: `{"id", "check": ...}` with
  - `"equal"`: `{"subject", "expected", "tolerance"}`, where the expected operand is `{"kind": "value", "expr"}`, `{"kind": "subject", "subject"}` or `{"kind": "list", "items": [{"kind": "event", "event"} | {"kind": "value", "expr"}, ...]}`, and the tolerance `{"kind": "exact"}`, `{"kind": "abs", "tol"}` or `{"kind": "rel", "tol"}`;
  - `"within"`: `{"subject", "lo", "hi", "lo_closed", "hi_closed"}`;
  - `"outcome"`: `{"outcome": "initialization_fails" | "configuration_rejected"}`.
- Subject: `{"kind": "observation", "observation": id, "index": n | null}` (the n-th value of a series, from 1), `{"kind": "on", "expr", "event", "microstep"}` (`(e on E)`), `{"kind": "beat_start", "beat"}`, `{"kind": "beat_end", "beat"}`, `{"kind": "statistic", "statistic": "mean" | "deviation", "observation": id}` (PK-4.1a, D-084).
